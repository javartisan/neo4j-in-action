# 知识获取 · 精炼学习笔记

> 目标：快速抓住 NLP 抽取 / NER / RE / EE 的核心，能说清「从文本里怎么变成图谱里的点与边」。

---

## 一句话总览

**知识获取** = 从非结构化/半结构化数据中，自动或半自动抽出**实体、关系、事件**，供知识图谱入库。

| 要点 | 本质 | 输出长什么样 |
|------|------|----------------|
| NLP 抽取 | 端到端流水线（读文 → 抽知识） | 一套可入库的三元组/子图 |
| NER | 找出并分类「专有名词」 | `(贵州茅台, Company)` |
| RE | 判定实体之间的语义关系 | `(贵州茅台, BELONGS_TO, 白酒)` |
| EE | 抽出「发生了什么事」的结构 | `(事件类型, 论元角色…)` |

流水线关系：

```text
原文
 → NLP 预处理（分句/清洗）
 → NER（找实体）
 → RE（连关系） / EE（抽事件）
 → 对齐本体类型后写入图库（Neo4j 等）
```

与「知识表示」的分工：**表示**规定「能有哪些类与边」；**获取**负责「从文本里把实例填进去」。

---

## 1. NLP 抽取（总览）

### 核心定义

用自然语言处理技术，把研报、公告、新闻等文本，转成结构化知识（实体 + 关系 ± 事件）。

### 典型流水线（工程视角）

| 阶段 | 做什么 | 证券例子 |
|------|--------|----------|
| 文档解析 | PDF/DOCX/HTML → 纯文本 | 本仓库 `parser.extractTextFromFile` |
| 预处理 | 分句、去噪、编码统一 | 换行归一、去掉页眉页脚 |
| 实体层 | NER / 词典 / 正则 | 公司名、股票代码 `600519` |
| 关系层 | RE / 模板 / 依存 | 「属于…行业」「董事长是…」 |
| 事件层 | EE（可选） | 「定增事件」「并购事件」 |
| 后处理 | 去重、对齐本体、置信度过滤 | `Company`/`LISTED_AS` 规范化 |
| 入库 | MERGE 进图数据库 | 本仓库 `ingestExtractedGraph` |

### 三条技术路线（由易到难）

| 路线 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| **规则/词典** | 正则、模板、行业词表 | 可控、可解释、冷启动快 | 覆盖窄、维护成本高 |
| **传统 ML** | CRF/SVM + 特征工程 | 比纯规则泛化好 | 标注成本、特征繁琐 |
| **深度学习 / LLM** | BiLSTM-CRF、BERT、大模型提示 | 泛化强、少规则 | 贵、要评测与护栏 |

> 本仓库当前是 **规则 + 词典** 路线（见 `backend/src/services/parser.ts`），适合入门与可控演示；生产证券 KG 常 **规则保底 + 模型提召回**。

### 输入形态对照

| 输入 | 获取难度 | 策略 |
|------|----------|------|
| 结构化 JSON/CSV | 低 | 直接映射本体字段 |
| 半结构化表格/公告栏目 | 中 | 模板 + 字段对齐 |
| 纯文本研报/新闻 | 高 | NER + RE +（可选）EE |

### 速记

- NLP 抽取回答：**「文档进、子图出」**
- 没有本体约束的抽取 → 类型混乱，后面融合/推理很痛

## 2. NER（Named Entity Recognition，命名实体识别）

### 核心定义

在文本中定位实体的**边界**，并打上**类型标签**。

```text
输入：贵州茅台的股票代码是600519。
输出：
  [贵州茅台] Company
  [600519]   Stock
```

### 必须分清的两步

1. **识别（Detection）**：从哪到哪是一个实体（span）
2. **分类（Classification）**：这个 span 属于哪一类（Company / Person / …）

有的系统拆开做，有的端到端一次出「边界+类型」。

### 常见实体类型（通用 → 证券）

| 通用 NER | 证券领域常扩展 |
|----------|----------------|
| 人名 PER | 高管、实际控制人 |
| 机构 ORG | 上市公司、券商、基金 |
| 地点 LOC | 注册地、上市地（可选） |
| — | **股票代码、行业、产品、指标** |

本体里的类（`Company`/`Stock`…）= NER 标签集的设计来源。

### 工程做法速览

| 方法 | 直觉 | 适用 |
|------|------|------|
| 词典匹配 | 词表命中即实体 | 头部公司、标准行业名 |
| 正则 | `\b[036]\d{5}\b` 抓 A 股代码 | 强格式字段 |
| 序列标注 | BIO/BIOES + CRF/BERT | 开放文本、变体多 |
| LLM 抽取 | 提示「列出公司与代码」 | 快速试点、长尾 |

### 最小例子（对应本项目）

文本：`贵州茅台属于白酒行业，股票代码是600519。`

| span | 类型 |
|------|------|
| 贵州茅台 | Company |
| 白酒 | Industry |
| 600519 | Stock |

### 评价指标（知道名字即可）

- **精确率 P**：抽出的里面有多少是对的  
- **召回率 R**：该抽的里面抽到了多少  
- **F1**：P 与 R 的调和  

证券场景常更在乎：**代码/公司名别抽错**（精确）与 **别漏掉关键主体**（召回）的平衡。

### 速记

- NER 回答：**「文中有哪些东西、各是什么类型」**
- NER 只产**节点候选**，还没告诉你节点之间怎么连

## 3. RE（Relation Extraction，关系抽取）

### 核心定义

在已识别（或候选）实体之间，判定是否存在某种**预定义关系**，并给出方向。

```text
实体：贵州茅台(Company), 白酒(Industry), 600519(Stock)
关系：
  贵州茅台 —BELONGS_TO→ 白酒
  贵州茅台 —LISTED_AS→ 600519
```

### 和 NER 的衔接

```text
NER 出点  →  RE 出边  →  构成三元组 (头实体, 关系, 尾实体)
```

没有可靠 NER，RE 往往「连错对象」；没有 RE，图谱只是一堆孤立点。

### 关系从哪来

关系类型应来自**本体**（知识表示阶段定好），例如本项目：

`LISTED_AS` / `BELONGS_TO` / `HAS_EXECUTIVE` / `CONTROLS` / `COMPETES_WITH` …

### 三条常见做法

| 做法 | 说明 | 例子 |
|------|------|------|
| **模板/规则** | 匹配句式 | `X属于Y行业` → `BELONGS_TO` |
| **依存句法** | 用主谓宾/定中结构找论元 | 「茅台的董事长是丁雄军」 |
| **模型分类** | 给定实体对，判关系类型或无关系 | BERT 句对/实体标记分类 |
| **联合抽取** | NER+RE 一起学 | 减少流水线误差传递 |

### 最小例子（句式 → 三元组）

| 句子模式 | 抽出关系 |
|----------|----------|
| `X的股票代码是C` | `(X, LISTED_AS, C)` |
| `X属于Y行业` | `(X, BELONGS_TO, Y)` |
| `X的董事长是P` | `(X, HAS_EXECUTIVE, P)` |
| `X与Y存在竞争` | `(X, COMPETES_WITH, Y)` |
| `X控股Y` | `(X, CONTROLS, Y)` |

### 难点（面试常问）

1. **实体对组合爆炸**：一句话多个实体，要判「谁和谁有关」  
2. **关系方向**：控股是 A→B 还是 B→A  
3. **隐式关系**：句子没写「属于」，但上下文能推（更难）  
4. **跨句关系**：实体在第 1 句，关系线索在第 3 句  

### 速记

- RE 回答：**「这些实体之间是什么边」**
- 质量口诀：**先准关系类型，再补覆盖率**（错边进图谱比漏边更难洗）

## 4. EE（Event Extraction，事件抽取）

### 核心定义

从文本中识别**事件类型**，并抽出事件的**论元（参与角色）**——谁、对谁、在何时、做了什么。

```text
句子：贵州茅台定增事件引发市场关注。
事件类型：定增（Seasoned Equity Offering）
论元示例：
  主体公司 = 贵州茅台
  （可选）时间 / 规模 / 用途 …
```

### 和 RE 差在哪

| | RE | EE |
|--|----|----|
| 关注点 | 实体—实体的静态/长期关系 | 一次「发生」的结构化描述 |
| 输出 | 一条边/三元组 | 事件节点 + 多条角色边 |
| 例子 | 茅台属于白酒 | 茅台发起定增 |

可以同时存在：事件节点 `定增事件`，再用 `INVOLVES` 连到公司。

### 经典结构（ACE 风格直觉）

1. **触发词（Trigger）**：标志事件发生的词，如「并购」「回购」「中标」  
2. **事件类型（Type）**：并购 / 定增 / 减持 / 违规处罚…  
3. **论元角色（Argument Role）**：主体、标的、金额、时间、交易所…  

```text
[宁德时代] 宣布 [并购] [某电池材料公司]
   主体         触发词        标的
```

### 证券场景常见事件类型（举例）

- 股权：定增、减持、增持、回购、质押  
- 资本运作：并购、重组、分拆上市  
- 监管：处罚、问询、立案  
- 经营：中标、签约、业绩预告（可按需纳入）

### 工程落地层次

| 层次 | 做法 |
|------|------|
| 轻量 | 正则/词典抓触发词 → 建 `Event` 节点（本仓库偏这一档） |
| 标准 | 触发词检测 + 论元角色分类（序列标注/多头分类） |
| 增强 | 文档级事件、事件关系（因果、时序） |

### 速记

- EE 回答：**「发生了什么事、有哪些角色参与」**
- 图谱里常落成：**Event 节点 + INVOLVES/时间属性**，而不是硬塞进普通 RE

## 5 分钟自测

1. 知识获取与知识表示各负责什么？  
2. NER 的两步是什么？为什么说它只产「点」？  
3. RE 的标准输出形式是什么？关系类型应从哪里来？  
4. EE 与 RE 的核心差别？触发词是什么？  
5. 规则抽取与模型抽取如何分工最稳妥？

**参考答案要点**：  
①表示定模式，获取填实例  
②定边界+分类；尚未连边  
③`(头, 关系, 尾)`；来自本体  
④EE 描述一次发生及论元；触发词标志事件  
⑤规则保底与可解释，模型提召回，关键边人工/校验

---

## 建议学习顺序

1. 先固定领域 **实体类型 + 关系类型**（回看知识表示/本体）  
2. 用手写 10 条句子，标出 NER/RE 期望结果（建立语感）  
3. 实现或读懂一条 **规则流水线**（本仓库已具备）  
4. 再学序列标注 NER、句子级 RE  
5. 有公告/资讯场景时再深入 **EE 论元角色**
